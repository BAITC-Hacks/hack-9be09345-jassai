# Спутник: поставка участника C

23 сентября 2026. Основа — командный `main b956101`, включая актуальный Windows
launcher и демонстрационный набор A/B. Изменения не заменяют персонажа A:
реализованы комната, одежда, древо, диалог и точка подключения его GLB.

## Что можно показать

1. «Спутник» в главной навигации: текущая цель и следующий шаг с реальными
   уровнями до/после; вопрос «Зачем мне эта активность?» отвечает в облаке.
2. «Древо навыков»: пять уровней каждой ветви, текущие знания и требование
   цели, подходящие активности и их прогноз. Это фактические уровни, а не
   придуманные обязательные цепочки курсов.
3. «Гардероб»: десять вещей/комнат, понятные условия, примерка закрытых вещей,
   сохранение доступного образа. По умолчанию четыре базовых предмета.
4. Включить награды, выбрать личный квест, начать и завершить добровольную
   активность. После положительного прироста открываются соответствующие
   вещи. Импорт, сообщения, примерка и повторное завершение наград не дают.
5. После завершения показаны прирост навыков и новые предметы; у спутника
   появляется сообщение о результате и предусмотрено состояние `celebrate`.
6. OpenAI и NVIDIA возвращают потоковый текст для свободного вопроса, когда
   задан ключ выбранного провайдера. Простые объяснения работают локально.

Для демонстрации интерфейса без данных используется `/?preview=employee#companion`:
он явно подписан, хранит вымышленные изменения только в памяти, не вызывает AI.

- Два независимых просмотра интерфейса: desktop 1280 px и mobile 390 × 844.

  выхода страницы нет. Ошибок/warnings консоли при проверке не обнаружено.
- Реальный браузер и локальная SQLite, синтетический E2: включение → квест
  EV_BEFORE → начало → завершение. Architecture **1 → 4**, покрытие **20 → 80%**,
  **50 XP**, открыты кепка, блокнот и шапка квеста. Надетая кепка сохраняется
  после перезагрузки. Древо отражает четвёртый освоенный уровень.
- При смене сотрудника предыдущие сообщения исчезают. Локальные вопросы
  в браузере возвращали первый текст за **16–18 мс** в наблюдаемых попытках.
  Отдельный HTTP-замер: p95 **8,828 мс**, методика и ограничения —
  [COMPANION_PERFORMANCE.md](COMPANION_PERFORMANCE.md).
- Сервер проверяет роль, CSRF и владельца профиля, запрещает надеть закрытую
  вещь, сохраняет экипировку в SQLite. Тесты проверяют миграцию существующей БД,
  независимость наград от смены цели, импортов и обновления оценки.

## Что остаётся внешней зависимостью

- Финальный маскот A, его анимации и узлы одежды. Сейчас видны пустой подиум
  и отдельная примерка предмета; персонаж не подменяется новым рисунком.
  Подключение: [MASCOT_ASSET_CONTRACT.md](MASCOT_ASSET_CONTRACT.md).
- Живые ключи, проверка облачных моделей и их p50/p95; протоколы проверены
  mock-транспортом, реальные OpenAI/NVIDIA в этих тестах не вызывались.
- Голос и разговорный тренажёр клиента: сознательно оставлены в потенциале
  по решению пользователя. Пока нет STT/TTS и оценки качества устной речи.
- Постоянное защищённое хранение NVIDIA и единый мониторинг расходов; сейчас
  NVIDIA берётся из окружения сервера, OpenAI — из launcher B.

Награды не означают карьерное повышение. Учебная активность в этом прототипе
завершается сотрудником через существующий серверный сценарий; проверка знаний
внешней LMS и защита от фиктивного прохождения — будущая интеграция.

## Идеи следующего этапа

- «Репетиция сложного клиента»: короткая сценка, объяснение удачных действий,
  рекомендация навыка и повтор после курса. Вклад в древо только после
  проверяемого задания, а не по самопроизвольному мнению модели.
- «Почему именно этот шаг»: сравнение двух доступных активностей по времени,
  закрываемому разрыву и желаемой роли с сохранением решения пользователя.
- «Гардероб истории»: предмет показывает конкретные завершения, за которые
  заработан. Получается личная история профессионального роста.
- «Микрошаг на сегодня»: пользователь сам задаёт 15/30/60 минут; система
  выбирает существующее задание подходящей длительности, без штрафов за паузы.
- Анимация маскота отражает контекст — думает, объясняет, отмечает результат;
  микросостояние не подменяет измерение первого полезного ответа.
