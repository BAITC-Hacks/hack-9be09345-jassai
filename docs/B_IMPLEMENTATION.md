# Часть B — AI, launcher и проверка

Интеграционная основа: `main` на коммите `470aebb5ade8fcc62f530c7edcea86f3cf18dff9`,
контракт `docs/API_CONTRACT.md` версии 1.0. Сервер A, его lock-файл, README и
интерфейс C не заменены локальным прототипом. Добавлены только файлы B.

## Что добавлено

- `app/ai/provider.py`: `async def recommend(context)`, совместимый с A.
- `launcher.cmd`, `scripts/launcher.ps1`, `scripts/uv-manifest.json`: Windows x64 launcher.
- `tests/test_b_provider.py`: 28 синтетических проверок без сети и рабочего ключа.

AI выбирает порядок 1–3 допустимых кандидатов и минимум три разных фактора.
Responses API вызывается со строгой JSON Schema и `store=false`; модель
возвращает только ID/типы факторов. B проверяет их повторно и собирает текст
из фактов контекста A, не принимает свободный текст и придуманные уровни модели.
При нескольких кандидатах указывается альтернативный кандидат и фактический
компромисс по длительности, приросту, критичности, истории или формату.
Рекомендация развития не является решением о повышении или оценкой мотивации.

Ключ берётся из `OPENAI_API_KEY`, модель — `OPENAI_MODEL` (по умолчанию
`gpt-6-luna`). Модель должна быть доступна в конкретном API-проекте; launcher
проверяет доступ и поддержку схемы коротким запросом без данных сотрудников.
Бюджет B — 8 секунд на весь запрос; A ограничивает ожидание сверху девятью.
Сетевых повторов нет. Ключ, тело ошибки провайдера и профиль не включаются
в исключения. ФИО, employee_id и свободные описания мероприятий не отправляются
провайдеру. Все импортированные строки считаются данными, не инструкциями.

## Запуск на Windows 10/11 x64

1. Скачать **main**, распаковать архив, дважды нажать `launcher.cmd`.
2. Launcher проверяет SHA-256 закреплённого uv и выполняет `uv sync --locked
   --no-dev`, не меняя Python/PATH/firewall/политику PowerShell системы.
3. При настройке AI ввести действующий ключ в скрытом поле и модель.
   Перед отправкой реальных данных убедиться, что их обработка этим API разрешена.
4. Ключ проверяется без профиля и сохраняется через DPAPI текущего пользователя
   Windows, не в `.env` и не в открытом JSON. Пустой ввод допускает запуск без AI.
5. Сервер `app.main:app` слушает только `127.0.0.1` на свободном порте. После
   проверки `/health` и `/ready` открывается браузер. При первоначальной
   настройке одноразовый токен передаётся в URL **fragment**, не query/log.
6. Подключённый UI C создаёт HR и импортирует набор организаторов.
   Для ручной настройки через `/docs` следовать README; токен лежит в data dir.
7. Окно launcher оставить открытым; Ctrl+C останавливает его сервер. Закрытие
   вкладки не останавливает приложение. Повторный запуск открывает существующий
   проверенный экземпляр; БД и настройки не сбрасываются.

Все данные и окружение находятся вне репозитория:
`%LOCALAPPDATA%/CareerQuest/instances/hack-9be09345-jassai/`.
Для замены ключа после остановки сервера: `launcher.cmd /configure-ai`.
Для проверки установки, `/health`, `/ready` и выдачи UI без браузера и API-вызовов:
`launcher.cmd /check`. Созданный им проверочный сервер останавливается автоматически.
`CAREERQUEST_DATA_DIR` позволяет выбрать другую папку экземпляра (включая Python,
зависимости, БД и ключи). PowerShell 7 используется при наличии в PATH; иначе 5.1.
Launcher не изменяет ExecutionPolicy. Если выбранная среда запрещает скрипты,
он завершится с ошибкой; запуск на произвольном корпоративном ПК не гарантируется.
Для удаления только ключа/AI-настроек после подтверждения:
`launcher.cmd /disable-ai`; импорт и БД сохраняются.
Не отправлять `.dpapi`, `.env`, `setup-token.txt`, базу данных или логи на GitHub.
При запрете PowerShell обратиться к администратору устройства, не отключать защиту.

## Подключение к A и C

Launcher задаёт `CAREERQUEST_DATA_DIR`, `CAREERQUEST_AI_TIMEOUT=9` и, только
при наличии ключа, `CAREERQUEST_RECOMMENDER=app.ai.provider:recommend`.
При ручном запуске разработчиком задать эти переменные в окружении процесса;
секрет не вписывать в команды, README или tracked-файлы.

Ответ B точно соответствует `AIResult` A: `{recommendations:[{event_id,reason,
factors:[{type,text}]}]}`. A сохраняет авторизацию, CSRF, проверку доступности,
ревизии, cache invalidation и добавление серверного `event`.
AI-настройки фиксированы на время процесса; после смены модели/версии B
перезапустить сервер: A очищает кэш при старте. Сам B не создаёт второй кэш.

**Важное ограничение контракта v1.0:** A принудительно маркирует любой успешный
ответ callable как `mode:ai`. Поэтому B не подменяет сбой модели резервным
ответом внутри `recommend`. Ошибки идут штатным путём A: без подключённого
провайдера 503, тайм-аут 504, ошибка провайдера 502. C должен показывать их явно.

Функция `rules_fallback(context)` реализует отдельный многофакторный резервный
подбор с `mode:rules-fallback`. Он **ещё не подключён к HTTP/UI**: A/C должны
согласовать обработку отдельного режима. Нельзя установить его как
`CAREERQUEST_RECOMMENDER`, иначе A ошибочно назовёт его AI. Это оставшийся пункт
спецификации, а не заявленная готовая функция.

## Воспроизводимая проверка

Из корня командного репозитория:

```text
uv sync --locked
uv run pytest -q tests/test_b_provider.py
uv run pytest -q
```

Фактическая проверка B, 23.09.2026: `28 passed in 0.08s` в Linux с существующим
локальным Python-окружением, тесты без conftest прототипа. Это unit/contract
проверка B, **не** прогон всей части A и **не** чистая Windows.
Проверены: схема/приватность исходящего запроса, несуществующие/повторные ID,
недостаточные/повторные/неподтверждённые факторы, неизвестная/собственная
альтернатива, пустой результат, лишний текст, отсутствие ключа/кандидатов,
refusal/incomplete, ошибки API, общий deadline, отдельный fallback и статический
контракт launcher. Реальных расходов API тесты не создают.

## Интеграционная проверка A, 23.09.2026

Исправлены передача пути с завершающим обратным слэшем в CMD, изоляция
устанавливаемого Python, скрытый запуск серверного процесса и проверка
завершённости ответа при настройке ключа. На Windows с PowerShell 7 выполнены
первичная загрузка Python/uv/зависимостей и повторный `launcher.cmd /check`
из пути с кириллицей и пробелами. Сервер и UI доступны; проверочный сервер
завершился и удалил свой runtime-state. Это не проверка чистой Windows без
PowerShell 7: Windows PowerShell 5.1 на этой машине блокирует скрипты политикой.

Лимит ответа проверки ключа увеличен с 24 до 1024 токенов; для стандартной
`gpt-6-luna` выбран `reasoning.effort=none`. Это учитывает то, что лимит включает
reasoning-токены и может завершить ответ до выдачи текста: [OpenAI Docs](https://developers.openai.com/api/docs/guides/reasoning),
[параметры GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna).
Другим моделям этот параметр автоматически не навязывается.

Исправлено сравнение альтернатив без неверного утверждения об их приоритете.
UI сохраняет `reason`, а при отсутствии HTTP-настроек показывает действующую
инструкцию launcher. Резервный helper по-прежнему не подключён к HTTP.
Реальные ключ, Responses API и latency median/p95 остаются непроверенными.
