# Сценарий демонстрации — часть C

Статус: сценарий для интегрированной версии. Предпросмотр frontend/ не заменяет работающий backend/AI.

## Перед показом

- Настроить OpenAI через `launcher.cmd /configure-ai` и выполнить реальную рекомендацию до показа. Ключ вводится в скрытом поле launcher. NVIDIA и автоматический резерв пока не подключены.
- Проверить `launcher.cmd /check`, затем обычный запуск. Убедиться, что ошибка AI явно подписана.
- Подготовить разрешённые два файла нового профиля и истории, аккаунт сотрудника и аккаунт HR.
- Для завершения выбрать доступную self-paced/начатую активность; не завершать будущую очную сессию обходом дат.
- Проверить, что URL не содержит preview, аккаунты разграничены сервером, датасет/ключи не попали в видео или Git.

## Пять минут

| Время | Экран / доказательство |
|---|---|
| 0:00–0:25 | Проблема: сотруднику нужен понятный следующий шаг, HR — видимые дефициты |
| 0:25–1:15 | HR → Импорт: два файла, проверка, применение, новый профиль |
| 1:15–2:10 | Вход сотрудника: цель, критический разрыв, реальная рекомендация, минимум три фактора |
| 2:10–3:00 | Включить личные достижения и выбрать квест; завершить активность, показать прирост и покрытие до/после, XP и значок |
| 3:00–3:40 | HR: навыки с дефицитом, отсутствие подходящего шага, участие и период |
| 3:40–4:25 | Архитектура: сервер считает, LLM выбирает; показать фактические проверки |
| 4:25–5:00 | Пилот: принятие рекомендаций, завершение добровольных активностей, полезность объяснений |

Если AI отказал: показать сообщение ошибки и доступные шаги каталога, сохранность профиля и прогресса; не выдавать каталог за ответ модели. Если нет кандидатов: показать причину, а не выдуманный курс. Три разных фактора не означают три одинаковых фразы о разрыве.

Проверки перед сдачей: неизвестный ID; повторное завершение; отсутствие цели Lead; ограничения смены роли; некорректный импорт без частичной записи; повторный запуск; отказ AI; запрет HR API сотруднику. Результаты backend/launcher добавляют A/B после реального выполнения.
