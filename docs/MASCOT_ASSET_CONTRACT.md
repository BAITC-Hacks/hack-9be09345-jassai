# Подключение 3D-маскота команды

Сейчас сцена показывает объёмную комнату с пустым подиумом: самого маскота
добавляет A. Нового персонажа, лица или питомца в этой реализации нет.
При примерке предмет показывается отдельно на выставочной стойке.
В интерфейсе статус модели указан явно. При отсутствии WebGL навыки, гардероб и чат
остаются доступны. Ни один файл не загружается с CDN во время работы приложения.

## Встраивание

`frontend/mascot-renderer.js` экспортирует:

```js
const scene = mountMascot(host, {
  equipped: companion.equipped,
  previewItem: null, // полная вещь или стабильный id; только локальная примерка
  state: 'idle',
  modelUrl: '/static/assets/mascot/character.glb', // задавать после появления файла A
});
scene.update({equipped: updated.equipped, previewItem: null});
scene.setState('thinking');
scene.dispose(); // обязательно перед удалением DOM/сменой маршрута
```

Контейнер `[data-mascot-stage]` живёт внутри `.companion-room`. Над ним расположено
облако `#mascot-speech`, текст `#mascot-speech-text`, источник `#mascot-speech-source`.
Это обычный HTML: ответ можно показать сразу, не дожидаясь 3D-кадра.
Чат находится в отдельном `#companion-chat` и не зависит от отрисовки сцены.

`update` никогда не сохраняет одежду: запись делает только подтверждённый сервером
`POST` экипировки. `previewItem` может быть закрытой вещью. После примерки требуется
отдельное действие «Надеть»; закрытая вещь не имеет такого действия.

## Модель A

Формат — один самодостаточный **glTF binary (`.glb`)**, без внешних текстур и
скриптов. URL того же origin, рекомендуемый путь
`frontend/assets/mascot/character.glb`. Загрузка необязательна: пока URL не передан,
рендерер не делает заведомо неуспешных запросов за моделью.

- Y вверх; персонаж смотрит в +Z. Ступни на Y=0, персонаж по центру X/Z.
- Сцена автоматически центрирует модель, ставит на пол и нормализует высоту
  до 2.79 условных единиц. Рекомендуемая геометрия до 30 тысяч треугольников.
- Текстуры желательно до 1024², общий GLB желательно до 3 MB. Встроенные анимации
  с точными именами `idle`, `listening`, `thinking`, `speaking`, `celebrate`.
- Все состояния необязательны. Если анимации состояния нет, используется `idle`.
- Родительские узлы одежды имеют имена `item_<id>` из таблицы ниже. Потомки
  такого узла показываются вместе с ним. Узлы должны быть корректно привязаны
  к скелету внутри файла. Одежда выбирается видимостью узлов, без пересоздания GLB.
- Базовое тело должно оставаться видимым независимо от одежды. Не помещайте
  весь персонаж внутрь `item_body_starter`, иначе смена одежды скроет персонажа.
- Предметы `cap_starter` и `accessory_none` означают отсутствие предмета;
  отдельная геометрия для них не требуется.
- Комнаты рендерит сцена; отдельные узлы окружения внутри персонажа не нужны.

| Слот | ID предметов |
|---|---|
| `head` | `cap_starter`, `cap_spark`, `cap_quest` |
| `body` | `body_starter`, `body_explorer` |
| `accessory` | `accessory_none`, `accessory_notebook`, `accessory_compass` |
| `background` | `room_starter`, `room_horizon` |

Новые ID сначала добавляются в серверный каталог наград и согласовываются с
рендерером. Условия открытия описаны в [COMPANION_API.md](COMPANION_API.md).
При ошибке загрузки GLB остаются комната, примерочная и явное пояснение.

## Движение, скорость и управление

Рендер ограничен примерно 30 кадрами/с, DPR ≤ 1.6, карта тени 512². За пределами
экрана и на скрытой вкладке цикл останавливается. При `prefers-reduced-motion`
анимация и конфетти отключены; реакция отображается неподвижной позой.
Стрелки влево/вправо при фокусе на сцене поворачивают персонажа, Home сбрасывает
ракурс. Перетаскивание мышью также поворачивает модель. Вертикальный жест на
телефоне сохраняет прокрутку страницы.

Для ответа < 1 секунды приложение сначала показывает локальную реакцию и
обоснованный быстрый ответ в HTML-облаке. 3D и внешний AI не блокируют появление
текста. Это не обещание задержки внешнего API: фактическое время и источник
ответа должны отображаться в чате.

Three.js r170 поставляется локально в `frontend/vendor/`; лицензия MIT находится
рядом в `THREE_LICENSE.txt`. Исходный пакет `three@0.170.0`, upstream:
<https://github.com/mrdoob/three.js/tree/r170>.

## Подключение без изменения JavaScript

После добавления GLB в репозиторий измените `frontend/mascot-assets.json`:

```json
{"modelUrl":"/static/assets/mascot/character.glb"}
```

До появления модели значение `modelUrl` остаётся `null`. Приложение читает этот
манифест при открытии мастерской; пустой подиум сменится моделью после обновления
страницы. Сама модель и её экипировка должны соответствовать контракту выше.
