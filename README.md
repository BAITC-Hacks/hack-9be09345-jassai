# Career Quest — ИИ-навигатор развития сотрудника

Локальное веб-приложение команды JassAI для HackAlem AI, кейс 1 Halyk Bank.

**Реализована серверная часть A:** импорт JSON/CSV, SQLite, профиль и траектория, доступность мероприятий, изменение цели, завершение активностей, HR-аналитика, аккаунты и права доступа. Подготовлен интерфейс подключения AI. **Подключена часть C:** интерфейс сотрудника и HR, импорт, аккаунты, траектория, история, начало/завершение и формы OpenAI/NVIDIA. Launcher и настоящий AI-провайдер — часть B; реальная AI-интеграция пока не проверена.

## Устройство и технологии

| Компонент | Реализация |
|---|---|
| Сервер и API | Python 3.12.14, FastAPI 0.141.1, Uvicorn 0.53.0 |
| Проверка входных данных | Pydantic 2.13.5 |
| Хранение | SQLite, транзакции и постоянная БД вне репозитория |
| Сессии и права | Роли HR/employee, хэши паролей, HttpOnly cookie, CSRF |
| AI-интеграция | Подключаемая функция провайдера; проверка ответа, кэш и тайм-аут |
| Зависимости и тесты | `pyproject.toml`, `uv.lock`, pytest |

```text
app/main.py        HTTP API и подключение UI/AI
app/auth.py        аккаунты, сессии, проверки доступа
app/imports.py     проверка и атомарный импорт набора
app/domain.py      навыки, цели, доступность событий, HR-срезы
app/activities.py  начало/завершение активности, защита от повторного начисления
app/gamification.py добровольные личные квесты, XP, уровни и значки
app/db.py          SQLite и версия данных
app/models.py      схемы входных данных и ответа AI
```

Сервер сам рассчитывает уровни навыков и допустимые мероприятия. Подключаемый AI получает проверенный контекст, выбирает 1–3 шага и объясняет их. Сервер проверяет схему, идентификаторы и количество факторов; содержательную достоверность текста обеспечивает AI-провайдер. Без него API возвращает `503 ai_not_configured`, а не имитацию ответа модели.

## Запуск серверной части

Для текущего запуска разработчиком нужен **uv**; проверено с uv 0.12.18 на Windows и Python 3.12.14. Установка uv: [официальная инструкция](https://docs.astral.sh/uv/getting-started/installation/). Команды выполнять в распакованном репозитории:

```powershell
uv sync --locked
uv run python -m app init
uv run python -m app serve --port 8000
```

`uv` использует закреплённый Python из `.python-version`; если подходящего интерпретатора нет, его получение требует интернета. Сервер слушает только `127.0.0.1`.

Открыть [API-документацию](http://127.0.0.1:8000/docs). Проверки готовности: `/health` и `/ready`. Корневой адрес открывает интерфейс из `frontend/`; ресурсы обслуживаются на `/static/`. Launcher может передать одноразовый токен через `/#setup_token=TOKEN`.

БД по умолчанию: `%LOCALAPPDATA%/CareerQuest/instances/hack-9be09345-jassai/careerquest.sqlite3`. Для другой папки перед запуском задать `CAREERQUEST_DATA_DIR`. Повторный запуск сохраняет данные.

### Первичная настройка через API /docs (альтернатива интерфейсу)

1. Команда `init` выводит путь к `setup-token.txt`. Прочитать токен локально и вызвать `POST /api/setup` с `token`, `username`, `password` (минимум 10 символов). Первый аккаунт — HR; повторная настройка запрещена.
2. Вызвать `POST /api/auth/login` с этими данными. Браузер сохраняет cookie; из ответа взять `csrf_token`.
3. Для изменяющих запросов в `/docs` заполнять поле `x-csrf-token` полученным значением.
4. В `POST /api/hr/import/validate` загрузить четыре файла организаторов в поле `files`, режим `add`. Если `valid=true`, передать полученный `batch_id` в `POST /api/hr/import/apply`.
5. Создать аккаунт сотрудника через `POST /api/hr/users`: `username`, `password`, `role:"employee"`, `employee_id` из импортированного набора. Войти под ним для проверки `/api/me`.

Общие пароли и API-ключи с репозиторием не поставляются. Launcher, который автоматизирует подготовку окружения и открытие браузера, ещё не добавлен.

## Данные и конфигурация

Нужен разрешённый стартовый набор: `employees.json`, `events.json`, `skills.json`, `activity_history.csv`. Его получают у организаторов; в репозитории он не распространяется. JSON сохраняет исходные контейнеры `{meta, employees}`, `{meta, events}`, `{meta, skills, role_profiles, proficiency_scale}`.

Дата среза — `2026-10-01`. Навыки пересчитываются с учётом completed после `last_review_date`, `gain` и `max_level`. Обязательные мероприятия не рекомендуются. Для нового профиля можно импортировать только employees.json и историю; конфликты ID требуют явного режима `update`.

Параметры окружения описаны в `.env.example`; автоматического чтения `.env` нет. AI подключается через `CAREERQUEST_RECOMMENDER=app.ai.provider:recommend`. Для UI сервер обслуживает `frontend/index.html` и ресурсы по `/static/`; альтернативная папка — `CAREERQUEST_STATIC_DIR`.

Полный контракт для B и C: [docs/API_CONTRACT.md](docs/API_CONTRACT.md).

## Основной сценарий и проверка

| Действие | Ожидаемый результат |
|---|---|
| Сотрудник: `GET /api/me` | Профиль, история, цель, разрывы и допустимые следующие шаги |
| `POST /api/me/recommendations` | После подключения B: 1–3 шага с ≥3 различными факторами; сейчас без провайдера — 503 |
| `POST /api/me/activities/{event_id}/complete`, тело `{}`, заголовки `X-CSRF-Token` и `Idempotency-Key` | Для доступного self-paced события меняются навыки и траектория |
| Повторить завершение с тем же ключом | Возвращается тот же результат, повторного начисления нет |
| Перезапустить сервер | Навыки и история сохранены |
| HR: `GET /api/hr/overview` | Дефициты навыков, отсутствие следующего шага с причиной, участие по событиям |
| Включить «Достижения», выбрать личный квест и завершить его | XP за фактический рост навыков, значки и состояние квеста сохраняются |
| Сотрудник обращается к HR API | 403; чужие данные недоступны |
| Импортировать неизвестный профиль и историю | Они доступны без изменения кода; ошибочная партия не меняет БД |

Для события по расписанию требуется наступившая сессия; детали начала и завершения — в контракте API. Показатель покрытия требований не означает автоматическое повышение грейда.

Достижения по умолчанию выключены. Награда за добровольную активность с реальным приростом: `20 + 10 × полученные уровни навыков` XP. Импортированная история, обязательные мероприятия и повтор одного выполнения XP не дают. Накопленные награды сохраняются при отключении; HR их не видит. Правила, API и сценарий проверки: [docs/GAMIFICATION.md](docs/GAMIFICATION.md).

Автоматические проверки на независимых синтетических примерах:

```powershell
uv run pytest -q
```

Сквозная проверка на локальном наборе организаторов во временной БД:

```powershell
uv run python scripts/check_dataset.py "C:\путь\к\career_quest_dataset"
```

Проверяются импорт, новый профиль, завершение, повтор запроса, права и сохранение после перезапуска. Сценарий не обращается к реальной LLM. Результаты и границы проверки: [TEST_RESULTS.md](TEST_RESULTS.md).

## Интерфейс и защита — часть C

- [Интеграция с A и настройки для B](docs/FRONTEND_INTEGRATION.md).
- [Проверки UI и реального API](docs/FRONTEND_TEST_RESULTS.md).
- [Сценарий защиты](docs/DEMO.md).

В UI HR доступны импорт, таблицы развития и «Профили и доступ» для создания аккаунта нового сотрудника. После создания аккаунта сотрудник входит самостоятельно. Раздел «Доступные шаги» показывает допустимые сервером активности и работает без LLM; он явно не называется AI-рейтингом. В рекомендациях ошибка AI показывается отдельно, без выдуманного результата.

Настройки OpenAI/NVIDIA ждут подключения маршрутов B: до этого ввод ключей отключён. Отсутствующий реальный AI не считается выполненным критерием хакатона.

Изолированный предпросмотр UI: `python scripts/preview_ui.py`, затем `http://127.0.0.1:8765/?preview=employee` или `?preview=hr`. Вымышленные примеры явно помечены; изменения не сохраняются, API не вызывается. Это не запуск полного приложения.

Тесты интерфейса: `node --test tests/*.test.mjs`. Node.js не требуется для пользовательского запуска через Python/launcher.
