# Halyk Career Quest

**Карьерная цель → полезная активность → рост навыков → новые возможности.**

Кейс 1 Halyk Bank · HackAlem AI · команда JassAI. Career Quest помогает сотруднику понять, чему учиться и зачем, получить объяснимую рекомендацию и увидеть результат. HR видит дефициты команды, историю участия и сотрудников без подходящего следующего шага. Личный 3D-помощник **Ирбис** превращает развитие в квест с древом навыков и открывающимся гардеробом.

**В стартовых файлах есть данные 200 сотрудников.** Их не нужно создавать вручную: загрузите четыре файла в соответствующие поля импорта, проверьте и примените изменения. После применения профили доступны в разделе «Сотрудники». Для входа HR отдельно создаёт выбранным профилям логины и пароли.

**В подготовленном командой окружении AI уже подключён. Свой API-ключ пользователю вводить не нужно.** Запускайте настроенную версию и пользуйтесь рекомендациями и чатом. На отдельном компьютере подготовку AI выполняет команда: сохранённая настройка защищена Windows DPAPI и не переносится вместе с ZIP. Ключи в репозиторий не включены.

## Запуск: HR → импорт четырёх файлов → сотрудник

### 1. Запустить приложение

Нужны Windows 10/11 x64, браузер и интернет для первой установки и облачного AI. Python, Git, Node.js, Docker и Blender для обычного запуска вручную не устанавливаются. Для 3D нужен WebGL; остальные функции доступны и без него.

1. Скачать подготовленную версию команды либо выбрать **main → Code → Download ZIP** в [репозитории](https://github.com/BAITC-Hacks/hack-9be09345-jassai).
2. Полностью распаковать архив. Не запускать launcher из ZIP и не переносить его отдельно от остальных файлов.
3. Дважды нажать **[launcher.cmd](launcher.cmd)**. Он подготовит закреплённые uv/Python и зависимости, запустит локальный сервер и откроет браузер. Первый запуск может занять больше времени.
4. **Оставить окно launcher открытым.** Для остановки используется **Ctrl+C** в этом окне; закрытие вкладки сервер не останавливает.

В настроенном командном экземпляре AI используется сразу. Если другая установка предлагает ввести ключ, обратитесь к команде за настройкой этого компьютера: пользовательский сценарий не требует приобретать собственный API-доступ.

### 2. Создать первый аккаунт HR

На чистой базе откроется **«Первый запуск» → «Создайте аккаунт HR»**.

1. Придумать **логин HR** и **пароль от 10 символов**.
2. Нажать **«Создать аккаунт»**. Одноразовый токен launcher передаёт автоматически.
3. Приложение автоматически выполнит вход под HR.
4. Перейти в рабочее пространство. Если мастер предлагает загрузить данные — перейти к следующему шагу.

Первый HR создаётся один раз на локальную базу. Если появился обычный вход, аккаунт уже создан — используйте существующий логин. Удалять базу для повторного входа не нужно.

### 3. Загрузить 200 профилей через четыре ячейки

Открыть **HR → «Импорт данных»**. Выбрать файлы из папки **[starter-data/](starter-data/)** распакованного проекта. Каждый файл поместить в своё поле:

| Поле в приложении | Какой файл выбрать | Что загружается |
|---|---|---|
| **employees.json** | `starter-data/employees.json` | 200 профилей сотрудников: роль, грейд, оценки навыков, карьерные цели |
| **skills.json** | `starter-data/skills.json` | 60 навыков и 32 профиля требований: 8 ролей × 4 грейда |
| **events.json** | `starter-data/events.json` | 40 мероприятий с условиями участия и эффектом на навыки |
| **activity_history.csv** | `starter-data/activity_history.csv` | 2 743 записи истории участия |

Дальше:

1. Оставить режим **«Добавить новые записи»**.
2. Нажать **«Проверить файлы»**.
3. Дождаться сообщения **«Файлы прошли проверку»** и посмотреть отчёт.
4. Нажать **«Применить изменения»**. **Проверка сама по себе данные не сохраняет.**
5. Дождаться **«Данные загружены»** и перейти **«К сотрудникам»**.
6. В списке доступны профили набора; в **«Обзоре команды»** видно количество сотрудников, дефициты и участие.

Если часть данных уже была загружена, одинаковые записи будут **пропущены**, а не созданы повторно. Текущий код также умеет начальное заполнение пустой базы из `starter-data/`, поэтому повторная загрузка может показать «Добавлено: 0». Это нормально: проверяйте наличие профилей в списке. Для отдельной проверки именно пустого ручного импорта есть настройка разработчика ниже.

Файлы скачивания с названиями вроде `employees (1).json` и `activity_history (3).csv` можно выбрать в соответствующие поля без переименования. Важно содержимое и правильная ячейка.

**Все данные набора синтетические.** Дата расчётов — **2026-10-01**, история — за 24 месяца. Приложение использует дату среза из данных, а не дату компьютера.

### 4. Создать сотруднику доступ

1. Под HR открыть **«Сотрудники» → «Создать доступ»**.
2. В поле **«Сотрудник»** выбрать профиль, например **E0001 — Marat Yessenov**.
3. Задать ему отдельный уникальный логин и пароль от 10 символов.
4. Нажать **«Создать доступ»** и дождаться подтверждения.
5. Повторить для других сотрудников, которым нужен вход.

**Профиль и аккаунт — разные вещи.** Импорт создаёт карточку с данными. Кнопка «Создать доступ» создаёт логин для этой карточки. ID `E0001` сам по себе не является готовым логином или паролем. Не требуется выдавать доступ сразу всем 200 людям для демонстрации.

### 5. Войти сотрудником

Нажать **«Выйти»** из HR, затем ввести созданные логин и пароль и нажать **«Войти»**. Откроется **«Мой путь»**. Для импорта и управления доступом выйти и снова войти под HR.

При повторном запуске `launcher.cmd` аккаунты, история, навыки и экипировка сохраняются. Создавать HR и заново загружать набор каждый раз не нужно. Перед запуском обновлённой копии остановить предыдущую через Ctrl+C.

## Возможности сотрудника

| Раздел | Что делать |
|---|---|
| **Мой путь** | Смотреть роль, грейд и карьерную цель; менять цель; видеть покрытие требований и критические разрывы; получать 1–3 AI-рекомендации с объяснениями |
| **Навыки** | Сравнивать текущий и требуемый уровень, открывать деталь навыка, историю его изменения и подходящие активности |
| **Активности** | Искать занятия, выбирать «Все / Подходят мне / В процессе», фильтровать по формату, длительности и навыкам; смотреть требования и начинать доступный шаг |
| **История** | Смотреть статусы участия, находить начатые мероприятия, нажимать «Отметить выполнение» и открывать результат |
| **Спутник** | Общаться с Ирбисом, выбирать личный квест, смотреть древо навыков, примерять и надевать открытые предметы |

**«Что изменится»** показывает прогноз: уровни навыков, покрытие цели, критические разрывы и новые доступные активности. **«Сравнить варианты»** помогает сопоставить время и эффект альтернатив. Прогноз ничего не начисляет.

**«Начать» → «История» → «Отметить выполнение»** — основной цикл обучения. После завершения виден результат **«было → стало»**. Повторное нажатие не начисляет второй прирост. Сессию с датой позже даты среза завершить нельзя.

Если цель не задана, предлагается следующий грейд текущей роли. Для Lead следующий грейд не выдумывается. Покрытие требований показывает состояние навыков, а не обещание повышения. При отсутствии подходящего шага отображается причина.

### Как считается прогресс

За основу берутся навыки последней оценки. Отсутствующий навык равен 0. Затем учитываются завершения после `last_review_date`; новое завершение внутри приложения учитывается и в день этой оценки.

```text
новый уровень = старый + max(0, min(gain, max_level − старый, 5 − старый))
покрытие цели = 100 × сумма min(текущий, требуемый) / сумма требуемых уровней
```

Обязательные мероприятия исключены из рекомендаций развития. Проверяются текущая роль/грейд, prerequisites, даты и история. Уже завершённое мероприятие повторно не предлагается; исключение — отдельное допустимое посещение клуба **EV_036**. Модель выбирает среди разрешённых шагов, а факты, числа и допустимость проверяет сервер.

## Ирбис: маскот, чат и геймификация

**Ирбис — настоящий 3D-снежный барс в личном пространстве сотрудника.** Подключены GLB-модель, анимации дыхания и оглядывания. Раздел состоит из трёх вкладок: **«Мой спутник» → «Древо навыков» → «Гардероб»**.

### Что умеет Ирбис

- Объясняет, **зачем конкретная активность нужна и к какой цели ведёт**.
- Помогает разобраться в навыке, прогрессе, следующем шаге и условиях наград.
- Отвечает на собственный текстовый вопрос; ответ появляется в облаке и передаётся потоком. Есть кнопка **«Остановить ответ»**.
- Кнопки вопроса у следующего шага и в ветви древа передают контекст конкретной активности или навыка.
- Показывает выбранный образ: головные уборы и аксессуары прикрепляются к модели, чапан меняет оформление, комната — окружение.
- **«Оглянуться» / «Спокойно»** переключают движение; **«Пауза» / «Продолжить»** управляют анимацией. Модель можно повернуть мышью или стрелками, Home возвращает ракурс.

Типовые объяснения по фактам могут приходить локально; свободные вопросы используют подключённый AI. Источник ответа обозначен. Чат не может сам изменить навыки, записать на курс или выдать одежду. История переписки хранится в памяти страницы, не как постоянный архив. Голос, микрофон и озвучивание пока не реализованы.

При ограничении анимации системой движение отключается. Если WebGL или модель недоступны, остаются древо, гардероб и текстовый чат.

### Древо навыков и личный квест

Древо отражает реальные уровни навыков, требования цели, критические разрывы и доступные активности с прогнозом. Узлы — шкала освоения, а не выдуманная обязательная последовательность курсов.

Нажать **«Включить награды»**, выбрать доступную активность как личный квест и отдельно начать её в каталоге. Квест можно снять, участие — приостановить без потери накопленного.

```text
XP за добровольное завершение с приростом = 20 + 10 × полученные уровни навыков
Пороги уровней опыта: 0 / 60 / 150 / 300 / 500 XP
```

Награды выключены по умолчанию. Импорт, обязательные активности, переписка, завершение без прироста и повтор одного выполнения XP не дают. Награды и экипировка личные, HR их не видит.

### Гардероб

В каталоге 10 вариантов по четырём слотам: голова, одежда, аксессуар, комната. Закрытый предмет можно примерить, а надеть — только после открытия. Надетый образ сохраняется в SQLite и восстанавливается после перезапуска.

| Предмет | Условие открытия |
|---|---|
| Без головного убора, изумрудный чапан, без аксессуара, светлая студия | Доступны с начала |
| Кепка первого шага | 1 добровольное завершение с наградой |
| Блокнот открытий | Суммарно 2 полученных уровня навыков с наградами |
| Синий чапан исследователя | 3 разные активности с наградами |
| Компас роста | Суммарно 5 полученных уровней навыков с наградами |
| Шапка личного квеста | 1 выполненный личный квест с наградой |
| Комната с горизонтом | 150 XP |

## Возможности HR и новые данные

| Раздел | Возможности |
|---|---|
| **Обзор команды** | Дефициты навыков, критические разрывы, сотрудники без цели или подходящего шага, причины ограничений и участие по мероприятиям |
| **Сотрудники** | Поиск по имени/ID, фильтры отдела, роли и грейда; просмотр профиля; создание доступа |
| **Профиль сотрудника** | Цель, покрытие требований, навыки и история. HR не выполняет активности от лица сотрудника |
| **Импорт данных** | Четыре поля для файлов, проверка структуры и ссылок, отчёт, отдельное применение, добавление и явное обновление |
| **Настройки AI** | Статус модуля и информация о настройке командного экземпляра |

Период «вся история / 30 / 90 дней» ограничивает участие; навыки и цели относятся к дате среза. Доля дефицита считается среди сотрудников, которым этот навык нужен. Один человек может входить в несколько групп причин отсутствия шага.

**Добавление новых данных:** после начального набора можно загрузить только новые профили и историю, либо дополнить события/навыки. Используются те же поля и действия **«Проверить файлы» → «Применить изменения»**. Новому профилю затем создаётся доступ.

Режим **«Добавить новые записи»** пропускает полностью одинаковые записи и отклоняет конфликтующие изменения ID. Для намеренного изменения выбрать **«Обновить существующие по ID»**. Ошибочная партия не меняет базу; удаления импортом нет. Если база изменилась после проверки, проверить партию заново. Дата `meta.as_of_date` должна совпадать с текущим набором, ссылки — существовать в базе или этой же партии. Файлы UTF-8, максимум четыре по 8 MiB.

## Соответствие ТЗ

Все пять функций из раздела **Must-have** представлены в реализации. Таблица показывает, где их проверить; окончательное качество AI оценивается на реальных ответах и профилях жюри.

| Требование | Реализация и проверка |
|---|---|
| Профиль и карьерная траектория | «Мой путь», навыки, цель, роль/грейд, история и доступные следующие шаги |
| AI-рекомендация следующего шага | Подключённый провайдер выбирает 1–3 допустимые активности; при отсутствии кандидатов показывается причина |
| Объяснение минимум по трём факторам | Проверяемые факторы цели, разрывов, критичности, истории, формата и длительности; роль/грейд учитываются при доступности |
| Обновление прогресса | Завершение меняет навыки и покрытие цели, показывает «было → стало», сохраняет результат без двойного начисления |
| Простой HR-view | Дефициты, сотрудники без следующего шага с причинами, участие по активностям |
| Дополнительные проверочные профили | Импорт новых employees.json и activity_history.csv без изменения кода, затем доступ и подбор для нового сотрудника |

Для трёх профилей жюри повторить импорт, создать доступ и показать рекомендации с учётом всей истории. Низкий Public Speaking сам по себе не должен означать приоритет перед критичным для цели System Design. Неизвестные заранее профили нельзя считать пройденными до фактической проверки.

| Что необходимо учесть | Как это обеспечивается |
|---|---|
| Приватность | Сотрудник видит свой профиль; вовлечённость и личные награды не открыты коллегам. HR получает обзор по роли |
| Разграничение прав | Проверки на сервере, сессии, хэши паролей, CSRF и Origin; скрытия кнопок недостаточно и оно не заменяет эти проверки |
| Explainability | Причины рекомендации, прогноз и раскрытая формула продвижения |
| Запуск одной командой | `launcher.cmd` подготавливает окружение и открывает локальное приложение |
| Добровольность | Награды включаются и приостанавливаются самим сотрудником; нет штрафов, публичного рейтинга и XP за обязательные процессы |

Хранение локальное, но облачный AI получает ограниченный контекст и введённые сообщения. Это не полностью изолированный банковский контур; для реальных данных нужна согласованная схема внешней обработки. Локальный владелец Windows имеет доступ к файлам базы.

Опционально уже реализованы персональный квест, гардероб, древо, прогноз перехода по требованиям и мобильная адаптация. Обмен баллов, признание коллег, командные миссии, визуальный конструктор событий, прогноз оттока, мессенджеры/календарь и полная KZ-локализация не заявляются готовыми обязательными функциями.

## Демонстрация за несколько минут

1. Запустить приложение и создать HR. Загрузить четыре файла в соответствующие поля, проверить и применить. Показать 200 профилей и HR-обзор.
2. Создать доступ сотруднику, выйти из HR и войти им. Показать цель, разрывы и AI-рекомендацию с тремя факторами.
3. Открыть **«Что изменится»**, затем Ирбиса. Задать вопрос о навыке и показать объяснение в облаке.
4. Включить награды и выбрать личный квест; отдельно начать активность, затем отметить выполнение в истории.
5. Показать результат, древо, новые вещи и сохранение образа после обновления страницы.
6. Вернуться HR и показать добавление нового профиля и его истории — сценарий проверки жюри.

Для точного числового примера можно дополнительно импортировать четыре файла из [demo/](demo/) и создать доступ **DEMO_E001**. Выбрать квест **«Практика проектирования сервисов (демо)»**, `DEMO_EV_DESIGN`, начать и завершить: проектирование **2 → 4**, покрытие **55,6% → 77,8%**, **+40 XP**, открываются кепка, блокнот и шапка квеста. Дата и ID demo совместимы со стартовым набором. Повторное завершение не начисляет результат снова.

## Технологии, хранение и проверки

```text
launcher.cmd → uv / Python → FastAPI → браузер: HTML/CSS/JS + Three.js
                               │
                    SQLite + правила навыков
                               │
                   AI-провайдер → проверка ответа
```

- **Backend:** Python, FastAPI, Pydantic, SQLite, httpx; [app/](app/).
- **Frontend:** JavaScript ES modules, локальные ресурсы, Three.js 0.170.0; [frontend/](frontend/).
- **Ирбис:** GLB и исходники в [assets/snow_leopard/](assets/snow_leopard/); manifest [mascot-assets.json](frontend/mascot-assets.json).
- **AI:** OpenAI для основного подбора и настроенного launcher-чата. В серверном адаптере есть NVIDIA для ручной конфигурации; обычный launcher использует собственную сохранённую настройку и очищает унаследованные AI-переменные.
- **Запуск:** [launcher.cmd](launcher.cmd), [scripts/launcher.py](scripts/launcher.py), закреплённые зависимости [uv.lock](uv.lock). Отдельной frontend-сборки для запуска нет.

По умолчанию данные находятся в `%LOCALAPPDATA%\CareerQuest\instances\hack-9be09345-jassai\`: `careerquest.sqlite3`, защищённые настройки, логи и окружение. Повторное скачивание исходников не сбрасывает эту базу. Другой компьютер или `CAREERQUEST_DATA_DIR` — отдельный экземпляр, без автоматической синхронизации аккаунтов.

Проверка запуска без браузера и AI-запросов:

```powershell
.\launcher.cmd /check
```

Для разработчика с `uv` и Node.js:

```powershell
uv sync --locked
uv run pytest -q
node --test tests/*.test.mjs
uv run python scripts/check_dataset.py starter-data
uv run python scripts/check_dataset.py demo
```

Тесты проверяют импорт, роли/CSRF, формулы, повторные завершения, сохранение, награды, маскота и контракты AI. В автоматических тестах внешний AI подменён: они не измеряют качество или задержку настоящей модели. Подключение команды и результаты тестов не являются гарантией ответа быстрее секунды.

Ручной сервер: `uv run python -m app init`, затем `uv run python -m app serve --port 8000`. API-схемы доступны на `/docs`. Для проверки пустого ручного импорта разработчик задаёт **новый** `CAREERQUEST_DATA_DIR` и `CAREERQUEST_SEED_DATA_DIR=off` до запуска; это отдельная база, для неё командную AI-настройку нужно подготовить отдельно. Рабочую базу удалять не требуется. `.env` автоматически не читается.

## Если что-то не работает

| Ситуация | Действие |
|---|---|
| Импорт проверен, но профилей нет | Нажать **«Применить изменения»**, дождаться «Данные загружены», открыть «Сотрудники» |
| При импорте «Добавлено: 0», записи пропущены | Набор уже есть; одинаковые профили не дублируются |
| Конфликт ID или ошибка ссылки | Исправить данные; для намеренного изменения существующей записи выбрать явное обновление и повторить проверку |
| Нельзя войти по E0001 | HR должен создать выбранному профилю отдельный логин и пароль |
| Появилась настройка AI или AI недоступен | Убедиться, что запущен подготовленный командой экземпляр под нужным Windows-пользователем; обратиться к команде для восстановления подключения |
| Нет модели Ирбиса | Обновить страницу, проверить WebGL и полноту распакованного архива; древо, гардероб и чат остаются доступны |
| Нет XP после импорта | Импорт не выдаёт награды. Нужны включённые награды и новое добровольное завершение с фактическим приростом |
| Видны только демонстрационные данные интерфейса | Убрать `?preview=employee` или `?preview=hr` из URL и войти в реальное приложение |
| Не запускается установка | Проверить интернет к GitHub/PyPI и запись в каталог. Диагностика: `logs/launcher.log`, `logs/server.stderr.log` в каталоге данных |

## Ограничения и дальнейшие идеи

Сейчас общение с Ирбисом текстовое. Голос/STT/TTS, разговорный тренажёр банковского клиента и задержка голосового ответа менее секунды — следующий этап. Прохождение отмечает сотрудник: встроенной LMS, видеоуроков, экзамена и независимого подтверждения компетенций пока нет. Интерфейс русский; KZ-перевод, постоянные уведомления, самостоятельный сброс пароля, SSO и корпоративные интеграции ещё не готовы.

Идеи развития:

- **Репетиция сложного клиента:** Ирбис разыгрывает ситуацию, объясняет удачные действия и связывает разбор с нужным навыком; сначала текст, затем голос.
- **Паспорт награды:** у каждой вещи видны задания и реальные приросты, благодаря которым она открылась.
- **Карьерные экспедиции:** маршрут к цели через настоящие требования и доступные активности, без выдуманных обязательных курсов.
- **Микрошаг на сегодня:** выбрать 15/30/60 минут и получить существующее задание подходящей длительности.
- **Совместная миссия с наставником:** добровольная практика и проверяемый результат без рейтинга сотрудников.
- **HR-запрос на новое обучение:** из причины отсутствия шага сформировать черновик нужного курса, который подтверждает HR.

В пилоте оценивать принятие рекомендаций, завершение добровольных активностей, явку, полезность объяснений, изменение покрытия навыков и стоимость/задержку AI. Эффект на мотивацию и экономию бюджета — гипотеза для пилота, а не доказанный результат синтетического набора.
