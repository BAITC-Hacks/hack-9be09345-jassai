# Career Quest — ИИ-навигатор развития сотрудника

Кейс 1 Halyk Bank, HackAlem AI · команда JassAI.

Локальное веб-приложение для сотрудника и HR. Сотрудник выбирает карьерную цель, видит дефициты навыков, получает объяснимые AI-рекомендации и завершает учебные активности. Личный 3D-спутник — снежный барс — показывает прогресс через древо навыков, добровольные квесты и заработанный гардероб. HR импортирует данные, создаёт доступ и анализирует развитие команды.

## Запуск для жюри

**Windows 10/11 x64, браузер и интернет для первой установки.** Python, Git, Node.js, Blender и права администратора для обычного запуска не нужны. Для 3D требуется WebGL; без него профиль, древо, гардероб и текстовый чат остаются доступны.

1. На GitHub выбрать **main → Code → Download ZIP**, распаковать архив целиком в доступную для записи папку.
2. Дважды нажать **[launcher.cmd](launcher.cmd)**. Он скачает закреплённые uv и Python, проверит SHA-256 uv, установит зависимости из `uv.lock`, запустит сервер и откроет браузер. Первый запуск дольше повторных.
3. Настройку OpenAI можно пропустить: основной сценарий и локальные объяснения спутника работают без ключа. Для облачного AI ввести собственный ключ в скрытом поле launcher; короткий запрос проверит модель без данных сотрудников. Ключ сохраняется через Windows DPAPI текущего пользователя.
4. В браузере создать первый аккаунт **HR**: собственный логин и пароль от 10 символов. Одноразовый токен настройки launcher передаёт автоматически.
5. В **«Импорт данных»** выбрать четыре файла из [demo/](demo/): `employees.json`, `events.json`, `skills.json`, `activity_history.csv`. Нажать **«Проверить файлы» → «Применить изменения»**.
6. В **«Сотрудники» → «Создать доступ»** создать аккаунт для **DEMO_E001 — Демо Участник 01**, задать отдельные логин и пароль. Выйти из HR и войти сотрудником. ID профиля не заменяет логин.

Окно launcher оставить открытым. **Ctrl+C** останавливает его сервер; закрытие вкладки браузера сервер не останавливает. Повторный запуск сохраняет БД, аккаунты, достижения и одежду. Перед запуском новой копии проекта остановить предыдущую; повторный запуск той же копии открывает уже работающий экземпляр.

| Команда из папки проекта | Назначение |
|---|---|
| `.\launcher.cmd` | Подготовить окружение и открыть приложение |
| `.\launcher.cmd /check` | Проверить установку, сервер и выдачу UI; без браузера и AI-запросов, с остановкой проверочного сервера |
| `.\launcher.cmd /configure-ai` | Подключить или заменить ключ и модель после остановки сервера |
| `.\launcher.cmd /disable-ai` | Удалить AI-настройки после подтверждения, сохранить БД |
| `.\launcher.cmd /help` | Показать параметры запуска |

При прерванной установке проверить доступ к GitHub/PyPI и возможность записи в каталог данных, затем повторить запуск. Launcher использует встроенный Windows PowerShell для загрузки и проверки uv; PowerShell-скрипты и изменение execution policy не требуются. Диагностика находится в `logs/launcher.log` и `logs/server.stderr.log` каталога данных.

## Устройство проекта и технологии

```text
Браузер: профиль / HR / спутник / Three.js
    ↓ HTTP + cookie-сессия; потоковый чат NDJSON
FastAPI → правила навыков и активностей → SQLite
       → допустимые кандидаты → OpenAI → проверка рекомендации
       → локальный ответ спутника или настроенный облачный чат
launcher.cmd → закреплённые uv/Python → scripts/launcher.py → сервер
```

| Компонент | Технологии и ответственность |
|---|---|
| [app/main.py](app/main.py), [app/models.py](app/models.py) | Python 3.12.14, FastAPI 0.141.1, Uvicorn 0.53.0, Pydantic 2.13.5; API, схемы и выдача UI/модели |
| [app/domain.py](app/domain.py), [app/activities.py](app/activities.py) | Навыки, карьерная траектория, доступность мероприятий, начало и завершение |
| [app/db.py](app/db.py), [app/imports.py](app/imports.py), [app/auth.py](app/auth.py) | SQLite, атомарный импорт, версии данных, роли HR/employee, scrypt, HttpOnly-сессии и CSRF |
| [app/ai/provider.py](app/ai/provider.py) | httpx 0.28.1, OpenAI Responses API, строгая JSON Schema; выбор 1–3 шагов и минимум трёх разных факторов |
| [app/gamification.py](app/gamification.py), [app/companion.py](app/companion.py) | Личные квесты, XP, значки, постоянные награды, экипировка и фактическое древо навыков |
| [app/companion_chat.py](app/companion_chat.py) | Локальные объяснения; потоковый OpenAI/NVIDIA для свободного вопроса, отмена, тайм-аут и кэш |
| [frontend/](frontend/), [frontend/mascot-renderer.js](frontend/mascot-renderer.js) | HTML/CSS, JavaScript ES modules и Three.js 0.170.0; без Node.js-сборки и CDN во время работы |
| [assets/snow_leopard/](assets/snow_leopard/) | GLB для браузера, редактируемый Blender-файл, текстуры, анимации, превью и исходники генератора |
| [scripts/launcher.py](scripts/launcher.py), [scripts/uv-manifest.json](scripts/uv-manifest.json) | uv 0.12.17 с SHA-256, изолированное окружение, управление процессом и DPAPI |
| [tests/](tests/), [uv.lock](uv.lock) | pytest, Node test runner и закреплённые Python-зависимости |

Сервер рассчитывает навыки по оценке и последующим завершённым активностям с учётом `gain`/`max_level`. AI не получает обязательные, уже завершённые, недоступные по требованиям мероприятия и шаги без прироста к цели. Исключение для повторов — новое допустимое посещение клуба `EV_036` в другую дату. Модель выбирает ID и факторы; объяснения собираются из проверенных фактов. Сервер повторно проверяет ответ и актуальность данных. AI не меняет БД; покрытие требований не означает автоматическое повышение грейда.

UI и API доступны через один сервер на `127.0.0.1` и свободном порте. Полная спецификация — `/docs` и `/openapi.json` по адресу приложения.

| Группа API | Основные маршруты |
|---|---|
| Готовность и доступ | `/health`, `/ready`, `/api/setup`, `/api/auth/login`, `/api/auth/session` |
| Сотрудник | `/api/me`, `/api/me/goal`, `/api/me/recommendations`, `/api/catalog` |
| Активности и достижения | `/api/me/activities/{event_id}/start`, `/api/me/activities/{event_id}/complete`, `/api/me/gamification`, `/api/me/gamification/quest` |
| Спутник | `GET /api/me/companion`, `POST /api/me/companion/equip`, `POST /api/me/companion/chat` |
| HR | `/api/hr/users`, `/api/hr/employees`, `/api/hr/overview`, `/api/hr/import/validate`, `/api/hr/import/apply` |

Изменяющие авторизованные запросы требуют `X-CSRF-Token`; завершение — также `Idempotency-Key`. Повтор завершения с тем же ключом возвращает сохранённый результат без повторного прироста или XP. Чат возвращает NDJSON: `status`, `delta`, затем `done` либо `error`. Сотрудник не получает чужие профили и HR API; HR не видит личные XP, квесты, гардероб и чат сотрудника.

Рабочие ветки распределены по частям проекта; `main` и `integration` содержат общую проверенную версию на момент поставки:

```text
main                  версия для скачивания и запуска
├── codex/c-ui        интерфейс, спутник и демонстрация — C
├── feature-ai        AI и проверочные ситуации — B
├── launcher          установка и запуск — B
└── integration       объединение сервера A, AI/launcher B и UI C
```

Это распределение ответственности, а не вложенные каталоги. Исторические ветки сохранены; для запуска не требуется объединять их вручную.

## Данные и настройки

Первый импорт принимает четыре файла. JSON-контейнеры: `{meta, employees}`, `{meta, events}`, `{meta, skills, role_profiles, proficiency_scale}`; история — CSV. Дата расчётов берётся из `meta.as_of_date`; в демонстрации это **2026-10-01**. Последующие партии могут содержать только `employees.json` и/или `activity_history.csv`. Режим `add` не перезаписывает конфликтующие ID; `update` выполняет явное обновление. Ошибочная партия не меняет БД; после изменения исходных данных нужна новая проверка партии.

[demo/](demo/) содержит 3 вымышленных сотрудника, 4 навыка, 8 профилей роли/грейда, 8 мероприятий и 5 записей истории. Реальных сотрудников, ключей и готовых аккаунтов нет. Разрешённый набор организаторов можно импортировать вместо демонстрационного; рабочие данные компании не распространяются в репозитории.

Данные launcher находятся вне репозитория:

```text
%LOCALAPPDATA%\CareerQuest\instances\hack-9be09345-jassai\
  careerquest.sqlite3   аккаунты, данные, история, достижения и экипировка
  settings/            защищённый ключ и параметры AI
  logs/, runtime/      диагностика и сведения о запущенном экземпляре
  tools/, python/, venv/, uv-cache/   окружение исполнения
```

Для независимого чистого экземпляра задать `CAREERQUEST_DATA_DIR` на другую папку перед запуском. Полный список переменных — [.env.example](.env.example); автоматического чтения `.env` нет. Изменение настроек требует перезапуска сервера.

| Режим | Настройка |
|---|---|
| Без облачного AI | Импорт, профили, каталог, прогнозы, завершение, спутник, локальные ответы и награды работают без ключа |
| OpenAI через launcher | `/configure-ai`: ключ защищён DPAPI; используется для рекомендаций и свободного чата. Модель по умолчанию — `gpt-6-luna` |
| OpenAI при ручном запуске сервера | `OPENAI_API_KEY`, `OPENAI_MODEL`, `CAREERQUEST_RECOMMENDER=app.ai.provider:recommend`; отдельная модель чата — `OPENAI_COMPANION_MODEL` |
| NVIDIA при ручном запуске сервера | `NVIDIA_API_KEY`, `CAREERQUEST_COMPANION_PROVIDER=nvidia`, `NVIDIA_COMPANION_MODEL` (по умолчанию `meta/llama-3.1-8b-instruct`). Только чат спутника; основной подбор остаётся OpenAI |

Launcher очищает унаследованные ключи провайдеров и передаёт серверу только настроенный OpenAI из DPAPI. NVIDIA через launcher не подключается и постоянно не сохраняется. При ручном запуске чат в режиме `CAREERQUEST_COMPANION_PROVIDER=auto` выбирает OpenAI, затем NVIDIA, если ключа OpenAI нет; повторного платного запроса к другому провайдеру после ошибки нет.

Ключи не вводятся в браузере, не включаются в командную строку или Git. Основной подбор передаёт факторы развития без ФИО, ID сотрудника и свободных описаний мероприятий. Облачный чат передаёт обезличенные факты профиля, названия доступных активностей, вопрос и до шести сообщений истории; введённый пользователем текст может содержать персональные данные. Для реальных данных требуется разрешение на внешнюю обработку. Локальная авторизация не скрывает SQLite от владельца Windows-аккаунта.

## Основной сценарий и правила наград

После запуска и импорта `demo/` войти аккаунтом **DEMO_E001**:

1. Открыть цель **Инженер → Senior**: проектирование сервисов — уровень **2**, покрытие требований — **55,6%**, один критический разрыв. Найти **«Практика проектирования сервисов (демо)»**, `DEMO_EV_DESIGN`, и посмотреть прогноз.
2. При подключённом OpenAI запросить рекомендацию: 1–3 допустимых шага, объяснение и минимум три разных фактора. Без настройки отображается явная ошибка; обычные шаги каталога остаются доступны.
3. Открыть **«Спутник»**: модель барса дышит, моргает и оглядывается. В **«Древо навыков»** проверить текущий уровень и требование цели. Нажать **«Зачем мне эта активность?»**: появится фактическое локальное объяснение с указанием источника. Оно не выдаётся за ответ LLM.
4. Включить добровольные награды и выбрать `DEMO_EV_DESIGN` личным квестом. По умолчанию участие выключено; импортированная история XP не даёт.
5. Начать мероприятие и завершить его через историю. Ожидается: навык **2 → 4**, покрытие UI **55,6% → 77,8%** (API **55,56% → 77,78%**), закрытый критический разрыв, **+40 XP**, два значка и завершённый квест. Открывается **«Надёжность сервиса: разбор отказов (демо)»**, `DEMO_EV_RELIABILITY`.
6. В **«Гардероб»** открываются **кепка первого шага, блокнот открытий и шапка личного квеста**. Примерить и явно надеть доступную вещь. Закрытую вещь можно примерить, но нельзя сохранить как экипировку; её примерка наград не даёт.
7. Обновить страницу и перезапустить приложение: покрытие, квест, XP и надетая вещь сохранены. Повтор завершения не даёт второй прирост или награду.
8. Войти HR: проверить дефициты и профиль **DEMO_E003** — Lead без цели и доступного следующего шага. Личные достижения и гардероб сотрудника в HR не отображаются.

Награда за добровольное завершение при включённом участии: **20 + 10 × сумма фактических приростов навыков**. Без прироста, за импорт, обязательную активность или повтор XP нет. Пороги уровней: **0, 60, 150, 300, 500 XP**. Пауза сохраняет накопленное; публичных рейтингов и штрафов нет. Нельзя завершить сессию позже `meta.as_of_date`. Завершение в прототипе подтверждает сотрудник; внешняя LMS и проверка знаний не подключены.

В гардеробе десять предметов. Условия основаны на неизменяемых записях наград; смена цели или обновление оценки не отбирают заработанное:

| Предметы | Условие |
|---|---|
| Без головного убора, **изумрудный чапан**, без аксессуара, светлая студия | Четыре базовых предмета доступны сразу |
| Кепка первого шага / блокнот открытий | 1 завершение с наградой / суммарно 2 уровня навыков с наградами |
| **Синий чапан исследователя** / компас роста | 3 разные активности с наградами / суммарно 5 уровней навыков с наградами |
| Шапка личного квеста / комната с горизонтом | 1 квест с наградой / 150 XP |

Одежда не меняет навыки, рекомендации и грейд. Открытие вещи не надевает её автоматически. Древо отражает реальные уровни 1–5: отметка «впереди» не создаёт вымышленных обязательных курсов; одна допустимая активность может поднять навык сразу на несколько уровней. Прогноз не считается завершённым прогрессом.

## 3D-спутник

[Irbis_SnowLeopard.glb](assets/snow_leopard/Irbis_SnowLeopard.glb) загружается с того же сервера по `/static/assets/mascot/character.glb`; путь задан в [frontend/mascot-assets.json](frontend/mascot-assets.json). В GLB один skinned mesh, **27 костей, 14 материалов и 6 встроенных текстур**; размер около **15,5 МиБ**. Blender для просмотра в приложении не нужен. Файлы модели и Three.js локальные; CDN не используется.

| Анимация | Длительность | Движение |
|---|---|---|
| `Idle_Breathe` | 5 секунд, цикл | Дыхание, моргание, хвост |
| `Idle_LookAround` | 8 секунд, цикл | Оглядывание, повороты головы и ушей |

Перетаскивание и стрелки влево/вправо поворачивают персонажа, **Home** сбрасывает ракурс. При системном `prefers-reduced-motion` движение отключается; на скрытой вкладке и вне экрана рендер приостанавливается. Недоступность WebGL или ошибка модели показываются явно и не блокируют текстовые функции. Облачный ответ не ждёт завершения 3D-анимации.

Редактирование: [Irbis_SnowLeopard.blend](assets/snow_leopard/Irbis_SnowLeopard.blend) и [Open_Model.cmd](assets/snow_leopard/Open_Model.cmd) требуют Blender 5.2+. В Action Editor у `IRBIS_Rig` выбрать клип; диапазоны — 120 или 192 кадра при 24 кадрах/с. [previews/](assets/snow_leopard/previews/) содержит ракурсы и видео/GIF, [source/](assets/snow_leopard/source/) — генератор. Мех стилизован текстурой и геометрией; симуляции волос и ткани нет.

Пересоздание ресурсов из корня проекта, если Blender и FFmpeg находятся в PATH:

```powershell
blender --background --python assets/snow_leopard/source/build_character.py
blender --background assets/snow_leopard/Irbis_SnowLeopard.blend --python assets/snow_leopard/source/render_previews.py
```

Первая команда перезаписывает модель, GLB и портрет; вторая рендерит циклы и ракурсы, затем кодирует видео/GIF через FFmpeg. Внешние AI-сервисы не нужны; промежуточные кадры находятся в `.runtime/`.

## Воспроизведение и проверка

Быстрая проверка установки без ключа: **`.\launcher.cmd /check`**. Для полного тестирования нужен `uv` в PATH, для тестов интерфейса — Node.js. Команды из корня проекта:

```powershell
uv sync --locked
uv run pytest -q
node --test tests/*.test.mjs
uv run python scripts/check_dataset.py demo
```

Проверяются атомарный импорт, новые профили, авторизация и CSRF, расчёты навыков, доступность мероприятий, повторные и параллельные завершения, сохранение после перезапуска, приватность наград и экипировки, контракты AI, потоковый чат, отмена и ошибки. AI-транспорт заменён синтетическими ответами; эти тесты не вызывают платный API. DPAPI-проверки выполняются на Windows и явно пропускаются на других ОС. `check_dataset.py` использует временную БД и принимает также путь к внешнему набору организаторов.

Установка launcher проверена на Windows из ZIP с пустым каталогом данных, кириллицей, пробелами и `&` в пути, без Python/uv/PowerShell 7 в PATH и при политике `Restricted`. Повторный `/check` прошёл с `UV_OFFLINE=1`. Это изолированное окружение на рабочем ПК, не отдельная чистая виртуальная машина. При первом запуске интернет всё равно нужен для зависимостей.

Для ручного запуска сервера:

```powershell
uv run python -m app init
uv run python -m app serve --port 8000
```

Открыть `http://127.0.0.1:8000/`. Для первоначальной настройки без launcher взять токен из `setup-token.txt` в каталоге данных и открыть `http://127.0.0.1:8000/#setup_token=TOKEN`. Токен не должен попадать в логи или Git. Поле `ai_configured` в `/ready` означает наличие провайдера, а не успешный вызов облачной модели.

**Границы проверки:** живые OpenAI/NVIDIA и качество их ответов без действующих ключей не подтверждены. Основной подбор при отсутствии настройки, сбое и тайм-ауте возвращает 503, 502 и 504. Локальные ответы спутника — ограниченный разбор намерений по фактам, не LLM. Свободный чат требует настроенного API; голос, STT/TTS и автоматическое выполнение действий отсутствуют. История чата хранится в памяти страницы и очищается при выходе или смене цели. Внешний ответ ограничен тайм-аутом, его задержка не гарантируется; предварительное сообщение «разбираю вопрос» не считается содержательным ответом.
