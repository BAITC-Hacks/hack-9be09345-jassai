# Career Quest — ИИ-навигатор развития сотрудника

Кейс 1 Halyk Bank, HackAlem AI · команда JassAI.

Локальное веб-приложение: сотрудник видит карьерную цель, дефициты навыков и подходящие мероприятия, получает объяснимые AI-рекомендации и фиксирует прогресс. HR импортирует данные, создаёт доступ сотрудникам и анализирует развитие команды. В разделе **«Спутник»** обучение развивает древо навыков, открывает одежду и комнаты; помощник объясняет следующий шаг в облаке сообщений.

Новая геймификация: **Мой спутник → Древо навыков → Гардероб**. Доступны 10 предметов, личный квест, примерка и сохранение экипировки. Награды начисляются только за фактический добровольный прогресс при включённом участии. Модель маскота добавляет A: подготовлены 3D-комната и подключение GLB, самого персонажа в этой поставке нет. Голос — следующий этап. [Механика и API](docs/COMPANION_API.md), [подключение модели](docs/MASCOT_ASSET_CONTRACT.md), [OpenAI/NVIDIA и скорость](docs/COMPANION_CHAT.md), [проверки новой версии](docs/COMPANION_DELIVERY.md).

## Запуск для жюри

**Windows 10/11 x64, браузер и интернет для первой установки.** Python, Git, Node.js и права администратора для обычного запуска не нужны. Готовая версия всех трёх частей находится в ветке **main**.

1. На GitHub выбрать **main → Code → Download ZIP**, распаковать архив целиком в доступную для записи папку.
2. Дважды нажать **[launcher.cmd](launcher.cmd)**. Он скачает закреплённые uv и Python, проверит SHA-256 архива uv, установит зависимости из `uv.lock`, запустит локальный сервер и откроет браузер. Первый запуск дольше повторных.
3. Подключение OpenAI необязательно: пропустить предложение настройки, чтобы проверить приложение без ключа. Для AI ввести собственный ключ в скрытом поле launcher; короткий запрос проверит модель без данных сотрудников. Ключ сохраняется через Windows DPAPI текущего пользователя.
4. В браузере создать первый аккаунт **HR** с собственным логином и паролем от 10 символов. Одноразовый токен настройки launcher передаёт автоматически.
5. На первом запуске данные уже загружены из [starter-data/](starter-data/): **200 сотрудников, 60 навыков, 32 профиля роли/грейда, 40 мероприятий и 2 743 записи истории**. Это синтетический набор организаторов; ручной импорт для чистой установки не нужен. Если база уже существовала, в **«Импорт данных»** нажать **«Проверить стартовый набор» → «Применить изменения»**, предварительно просмотрев отчёт.
6. В **«Сотрудники» → «Создать доступ»** выбрать профиль, например **E0001 — Marat Yessenov**, и задать ему отдельные логин и пароль. Выйти из HR и войти сотрудником. Данные профилей не создают готовые аккаунты или пароли.

Окно launcher оставить открытым. **Ctrl+C** останавливает его сервер; закрытие вкладки браузера сервер не останавливает. Повторный запуск сохраняет БД, аккаунты и достижения. Если экземпляр уже запущен, launcher открывает его страницу.

| Команда из папки проекта | Назначение |
|---|---|
| `.\launcher.cmd` | Подготовить окружение и открыть приложение |
| `.\launcher.cmd /check` | Проверить установку, сервер и выдачу UI; без браузера и AI-запросов, с остановкой проверочного сервера |
| `.\launcher.cmd /configure-ai` | Подключить или заменить ключ и модель после остановки сервера |
| `.\launcher.cmd /disable-ai` | Удалить AI-настройки после подтверждения, сохранить БД |
| `.\launcher.cmd /help` | Показать параметры запуска |

Если установка прервалась, проверить доступ к GitHub/PyPI и возможность записи в каталог данных, затем запустить launcher повторно. Он использует встроенный Windows PowerShell только для загрузки и проверки uv; PowerShell-скрипты и изменение execution policy не требуются. Ошибки сервера находятся в `logs/server.stderr.log`, сообщения launcher — в `logs/launcher.log` каталога данных, указанного ниже. Перед запуском новой копии остановить предыдущую.

Без ключа доступны импорт, профили, цели, каталог, расчёты, завершение активностей, достижения и HR. AI-рекомендация требует интернета, доступной модели и средств на API-аккаунте; каталог доступных шагов не выдаётся за ответ модели. NVIDIA и автоматический резервный подбор в текущий запуск не подключены.

## Устройство проекта и технологии

```text
Браузер (frontend/) → FastAPI (app/main.py) → правила развития → SQLite
                                         → допустимые кандидаты → OpenAI → проверка ответа
launcher.cmd → закреплённый uv/Python → scripts/launcher.py → локальный сервер
```

| Компонент | Технологии и ответственность |
|---|---|
| [app/main.py](app/main.py), [app/models.py](app/models.py) | Python 3.12.14, FastAPI 0.141.1, Uvicorn 0.53.0, Pydantic 2.13.5; HTTP API и проверка схем |
| [app/domain.py](app/domain.py), [app/activities.py](app/activities.py) | Расчёт навыков, траектории, допустимости мероприятий, начало и завершение активности |
| [app/db.py](app/db.py), [app/imports.py](app/imports.py) | SQLite, атомарный импорт JSON/CSV, версии данных, сохранение и идемпотентность |
| [app/auth.py](app/auth.py) | Роли HR/employee, хэши паролей scrypt, HttpOnly-сессии, CSRF |
| [app/ai/provider.py](app/ai/provider.py) | httpx 0.28.1, OpenAI Responses API и строгая JSON Schema; выбор 1–3 шагов и минимум трёх разных факторов |
| [app/gamification.py](app/gamification.py) | Добровольные личные квесты, награды за фактический прирост, уровни и значки |
| [frontend/](frontend/) | HTML/CSS, JavaScript ES modules; страницы сотрудника и HR, локальные шрифты и изображения, без сборки Node.js |
| [scripts/launcher.py](scripts/launcher.py), [scripts/uv-manifest.json](scripts/uv-manifest.json) | Windows launcher, uv 0.12.17 с проверкой SHA-256, изолированное окружение, DPAPI |
| [tests/](tests/), [uv.lock](uv.lock) | pytest и Node test runner; закреплённые зависимости для воспроизводимости |

Сервер рассчитывает навыки по оценке и последующим завершённым активностям с учётом `gain`/`max_level`. Из AI-кандидатов исключаются обязательные, уже завершённые и недоступные по требованиям мероприятия, а также шаги без прироста к цели. Исключение для повторов — новое допустимое посещение клуба `EV_036` в другую дату. Модель выбирает ID и факторы из допустимого контекста; объяснения строятся из проверенных фактов. Сервер повторно проверяет ответ и актуальность данных. AI не меняет БД; покрытие требований не означает автоматическое повышение грейда.

UI и API обслуживаются одним сервером на `127.0.0.1` и свободном порте. Спецификация API доступна на `/docs` и `/openapi.json` по адресу запущенного приложения.

| Группа API | Основные маршруты |
|---|---|
| Готовность и доступ | `/health`, `/ready`, `/api/setup`, `/api/auth/login`, `/api/auth/session` |
| Сотрудник | `/api/me`, `/api/me/goal`, `/api/me/recommendations`, `/api/catalog` |
| Активности и достижения | `/api/me/activities/{event_id}/start`, `/api/me/activities/{event_id}/complete`; `/api/me/gamification`, `/api/me/gamification/quest` |
| HR | `/api/hr/users`, `/api/hr/employees`, `/api/hr/overview`, `/api/hr/import/validate`, `/api/hr/import/starter`, `/api/hr/import/apply` |

Изменяющие авторизованные запросы требуют `X-CSRF-Token`; завершение — также `Idempotency-Key`. Повтор завершения с тем же ключом возвращает сохранённый результат без повторного прироста или XP. Сотрудник не получает доступ к HR API и чужим профилям.

## Данные и настройки

При старте сервера и `python -m app init` пустая база автоматически получает четыре файла из [starter-data/](starter-data/). Проверка схем, ссылок и дат и сама загрузка выполняются в одной транзакции. Повторный запуск не меняет уже существующий набор, аккаунты, цели, историю, XP и экипировку. Импортированная история участвует в расчёте навыков, но не начисляет игровые награды. Описания исходных данных сохранены на [русском](starter-data/README.ru.md), [казахском](starter-data/README.kz.md) и [английском](starter-data/README.md).

Для добавления данных HR открывает **«Импорт данных»**, выбирает нужные файлы и нажимает **«Проверить файлы» → «Применить изменения»**. После первой загрузки можно передать только новый `employees.json`, `activity_history.csv`, `events.json` или `skills.json`, а также любую их комбинацию. Для неизвестных менеджеров, навыков и мероприятий нужно включить связанные записи в эту же партию. Выбранные через форму файлы могут иметь имена скачивания вроде `employees (1).json`: поле формы определяет тип. JSON-контейнеры: `{meta, employees}`, `{meta, events}`, `{meta, skills, role_profiles, proficiency_scale}`; история — CSV. Все JSON должны иметь ту же `meta.as_of_date`, что и база: в стартовом наборе **2026-10-01**. Изменение даты среза не является операцией добавления.

Режим `add` добавляет новые ID, пропускает полностью совпадающие записи и отклоняет конфликтующие ID. `update` выполняет явное обновление после просмотра отчёта. Ошибочная партия не меняет БД; после изменения исходных данных партию нужно проверить заново. Кнопка **«Проверить стартовый набор»** читает комплект из приложения и работает в безопасном режиме добавления: пользовательские изменения не перезаписываются. Для новых профилей HR отдельно создаёт доступ сотрудника.

Небольшой набор [demo/](demo/) оставлен для воспроизводимой проверки: 3 вымышленных сотрудника, 4 навыка, 8 профилей роли/грейда, 8 мероприятий и 5 записей истории. Он независим от стартового комплекта. Оба набора не содержат реальных сотрудников, ключей или готовых аккаунтов.

Данные launcher хранятся вне репозитория:

```text
%LOCALAPPDATA%\CareerQuest\instances\hack-9be09345-jassai\
  careerquest.sqlite3   данные, аккаунты, история и достижения
  settings/            защищённый ключ и параметры AI
  logs/                сообщения launcher и сервера
  runtime/             сведения о запущенном экземпляре
  tools/, python/, venv/, uv-cache/   локальное окружение
```

Для отдельного чистого экземпляра перед запуском задать `CAREERQUEST_DATA_DIR` на другую папку. Полный список переменных — [.env.example](.env.example); автоматического чтения `.env` нет. При ручном запуске AI использует `OPENAI_API_KEY`, `OPENAI_MODEL` и `CAREERQUEST_RECOMMENDER=app.ai.provider:recommend`. По умолчанию модель — `gpt-6-luna`; выбранная модель должна быть доступна API-аккаунту. Настройки AI действуют на время процесса, после изменения нужен перезапуск.

Чтобы начать с пустого каталога данных без автоматической загрузки, установить `CAREERQUEST_SEED_DATA_DIR=off`. Для другого начального комплекта указать абсолютный путь к папке с четырьмя файлами канонических имён. Эта настройка влияет только на пустую базу; кнопка стартового набора всегда читает встроенный комплект. Команда `python -m app import <папка>` импортирует именно указанную партию и не добавляет стартовый комплект автоматически.

Ключ не включается в командную строку сервера или Git. Для рекомендаций во внешний AI передаются факторы развития без ФИО, ID сотрудника и свободных описаний мероприятий. Разговор спутника дополнительно передаёт вопрос, последние сообщения, цель, навыки и подходящие активности текущего сотрудника; для реальных данных необходимо разрешение на их внешнюю обработку. Локальная авторизация не скрывает БД от владельца Windows-аккаунта.

## Основной сценарий проверки

Для короткого воспроизводимого сценария ниже дополнительно импортировать `demo/` через HR (те же дата среза и уникальные ID позволяют добавить его к стартовому набору). Войти с логином, который HR создал для профиля **DEMO_E001** (ID профиля не заменяет логин):

1. Открыть цель **Инженер → Senior**: проектирование сервисов — уровень **2**, покрытие требований — **55,6%**, один критический разрыв. В разделе **«Активности»** найти **«Практика проектирования сервисов (демо)»**, ID `DEMO_EV_DESIGN`, и посмотреть прогноз.
2. Если подключён AI, запросить рекомендацию: отображаются 1–3 допустимых шага с объяснением и минимум тремя различными факторами. Без ключа отображается явная ошибка настройки; доступны обычные шаги каталога.
3. Открыть **«Спутник»**, включить награды и выбрать `DEMO_EV_DESIGN` как личный квест. Посмотреть ветвь навыка и задать вопрос «Зачем мне эта активность?». По умолчанию участие выключено, импортированная история XP не даёт.
4. Начать мероприятие и завершить его через историю. Ожидается: навык **2 → 4**, покрытие в UI **55,6% → 77,8%** (в API **55,56% → 77,78%**), критический разрыв закрыт, **+40 XP**, два значка и завершённый квест. Открываются кепка первого шага, блокнот и шапка личного квеста — их можно примерить и надеть в гардеробе. Также становится доступен шаг **«Надёжность сервиса: разбор отказов (демо)»**, `DEMO_EV_RELIABILITY`.
5. Обновить страницу и перезапустить приложение: результат сохранён. Повтор того же завершения не начисляет второй прирост или награду.
6. Войти HR: проверить дефициты, участие и сотрудника **DEMO_E003** — Lead без цели и доступного следующего шага. Личные XP и квесты сотрудника в HR не отображаются.

Награда за добровольное завершение при включённом участии: **20 + 10 × сумма фактических приростов навыков**. Без прироста, за импорт или обязательную активность XP нет. Пороги уровней: 0, 60, 150, 300, 500 XP. Пауза достижений сохраняет накопленное; публичных рейтингов нет. Нельзя завершить сессию, дата которой позже `meta.as_of_date`.

## Воспроизведение и автоматические проверки

Быстрая проверка готовности без ключей и браузера:

```powershell
.\launcher.cmd /check
```

Для разработки и полного тестирования нужен `uv` в PATH; для тестов интерфейса — Node.js. Команды из корня репозитория:

```powershell
uv sync --locked
uv run pytest -q
node --test tests/*.test.mjs
uv run python scripts/check_dataset.py demo
uv run python scripts/check_dataset.py starter-data
```

Тесты проверяют импорт и его атомарность, новые профили, авторизацию/CSRF, расчёты навыков, ограничения мероприятий, повторные и параллельные завершения, сохранение после перезапуска, приватность достижений, контракт AI и обработку его ошибок. AI-транспорт в тестах заменён синтетическими ответами; вызовов платного API нет. Windows-проверки DPAPI выполняются на Windows, на остальных ОС явно пропускаются. `check_dataset.py` использует временную БД и также принимает путь к внешнему набору организаторов.

Проверка версии со стартовым набором 23.09.2026: **216 Python-тестов и 89 тестов интерфейса прошли**. Проверены конкурентный первый запуск, отсутствие перезаписи и наград за импорт, добавление нового профиля с историей, конфликты и повторное применение. `check_dataset.py starter-data` подтвердил 200 профилей / 2 743 записи истории, импорт дополнительной партии, завершение активности и сохранение после перезапуска. В браузере проверены готовый HR-обзор на 200 сотрудников и повторный импорт: 0 добавлено, 0 обновлено, 3 075 сущностей пропущено. Тестовые аккаунты и базы в репозиторий не включены.

Проверено 23.09.2026 на Windows: **122 Python-теста и 55 тестов интерфейса прошли**. Установка из ZIP прошла с пустым каталогом данных, кириллицей, пробелами и `&` в пути, без Python/uv/PowerShell 7 в PATH и при системной политике `Restricted`. Повторный `/check` прошёл с `UV_OFFLINE=1`; проверочный сервер остановлен, рабочая папка осталась без `.venv`. В браузере пройден сценарий выше: импорт → доступ → квест → завершение → 40 XP; перезапуск сохранил 77,8% покрытия и завершённый квест. Передача адреса из launcher в браузер в этой проверке направлялась в тестовый браузер. Это проверка изолированного окружения на рабочем Windows-ПК, не отдельной чистой виртуальной машины.

Ручной запуск сервера для разработки:

```powershell
uv run python -m app init
uv run python -m app serve --port 8000
```

Открыть `http://127.0.0.1:8000/`. При первом запуске без launcher взять одноразовый токен из `setup-token.txt` в каталоге данных и открыть `http://127.0.0.1:8000/#setup_token=TOKEN`, подставив токен вместо `TOKEN`. Он не должен попадать в логи или Git. `/ready` показывает готовность сервера, необходимость настройки и наличие данных; `ai_configured` означает подключение провайдера, а не успешную проверку облачной модели.

Границы проверки: живой OpenAI и качество его выбора без действующего ключа не подтверждены; тестовый ответ API не является проверкой модели. При отсутствии настройки, сбое провайдера или тайм-ауте API возвращает соответственно 503, 502 или 504 и UI показывает ошибку. Запуск требует возможности скачать зависимости при первой установке; запрет исполняемых файлов или сети политиками организации launcher не отменяет.
