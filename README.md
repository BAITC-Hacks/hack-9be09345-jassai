# Career Quest — ИИ-навигатор развития сотрудника

Локальное веб-приложение для подбора следующих шагов развития сотрудника на основе профиля, истории участия и требований карьерной цели. Проект команды JassAI, HackAlem AI, кейс 1 Halyk Bank.

**Текущее состояние:** в репозитории находится только README. Исходный код, launcher, зависимости и тесты ещё не добавлены. Ниже описано проектируемое решение; запустить и проверить его сейчас невозможно.

## Устройство проекта

```text
Launcher → локальный сервер → интерфейс в браузере
                  ├── импорт профилей, навыков, мероприятий и истории
                  ├── SQLite: хранение данных и прогресса
                  ├── расчёт навыков, разрывов и доступных мероприятий
                  ├── LLM API: выбор и объяснение рекомендаций
                  └── HR: дефициты навыков и участие
```

Сервер рассчитывает актуальные навыки, требования цели и допустимость мероприятий. Модель выбирает 1–3 шага с учётом нескольких факторов. Сервер проверяет ответ модели и самостоятельно рассчитывает прирост навыков. Интерфейс сотрудника показывает личную траекторию, интерфейс HR — разрешённый обзор.

## Порядок запуска

Планируемое окружение: Windows 10/11 x64, браузер, интернет для первоначальной установки и обращения к AI, действующий API-ключ. Launcher должен подготовить Python и зависимости без их ручной установки.

Порядок после реализации:

1. Скачать репозиторий с GitHub и распаковать архив.
2. Запустить `launcher.cmd` и дождаться открытия браузера.
3. В мастере настройки создать локальную учётную запись и указать API-ключ.
4. Загрузить четыре файла стартового набора организаторов:

   | Файл | Назначение |
   |---|---|
   | `employees.json` | Профили и исходные навыки |
   | `skills.json` | Навыки и требования ролей/грейдов |
   | `events.json` | Мероприятия, условия участия и прирост навыков |
   | `activity_history.csv` | История участия |

5. Открыть профиль сотрудника. При повторном запуске данные и настройки должны сохраняться.

Датасет получают у организаторов; в репозитории его нет. API-ключ также не поставляется с проектом. Для воспроизводимого расчёта используется дата среза набора `2026-10-01`.

**`launcher.cmd` пока отсутствует.** Точные команды разработки, конфигурация модели и диагностика запуска будут документированы после проверки работающей версии.

## Основной сценарий

1. Сотрудник открывает профиль: роль, грейд, навыки, история и карьерная цель.
2. Получает 1–3 рекомендации с объяснением минимум по трём факторам: требования цели, разрывы навыков, критичность компетенций, история участия.
3. Отмечает активность выполненной. Навыки меняются по `gain` и `max_level`, обновляются прогресс и рекомендации.
4. HR просматривает дефициты компетенций, участие по мероприятиям и сотрудников без подходящего следующего шага.

## Воспроизведение и проверка

Приёмочный сценарий для будущей реализации:

| Действие | Ожидаемый результат |
|---|---|
| Запустить скачанную копию на втором компьютере | Launcher подготавливает окружение и открывает приложение |
| Импортировать новый профиль и историю в формате датасета | Профиль доступен без изменения кода |
| Получить рекомендацию | 1–3 допустимых мероприятия; каждое объяснено минимум тремя подтверждаемыми факторами |
| Завершить мероприятие | Прирост соответствует `gain` и `max_level`; траектория обновлена |
| Повторить запрос завершения | Повторного начисления нет |
| Перезапустить приложение | История и прогресс сохранены |
| Открыть HR-view | Видны дефициты, участие и отсутствие следующего шага с причиной |
| Запросить чужой профиль от имени сотрудника | Доступ запрещён |

При проверке учитывать: завершения после `last_review_date`, исключение обязательных мероприятий из рекомендаций, prerequisites, отсутствие цели и доступных событий. Повторное прохождение completed-мероприятий запрещено, кроме клуба `EV_036`.

Целевые задержки по ТЗ: интерфейс — до 2 секунд, AI-рекомендация — до 10 секунд; первоначальная установка измеряется отдельно. Автоматические тесты, команды их запуска и фактические результаты пока отсутствуют.
