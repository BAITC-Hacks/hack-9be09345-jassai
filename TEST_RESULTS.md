# Проверка серверной части A и интеграции C

Проверено 23 сентября 2026 года на Windows, Python 3.12.14. Проверены сервер, интерфейс C и личные достижения. Реальная LLM без ключа не проверялась.

## Автоматические тесты

Команда: `uv run pytest -q` (при разработке выполнена эквивалентная команда `python -m pytest -q` в окружении с закреплёнными зависимостями).

**65 passed за 102,22 секунды**, включая 27 проверок геймификации. Тесты интерфейса: `node --test tests/*.test.mjs` — **27 passed**.

Проверены:

- одноразовая первичная настройка, вход, сессии, выход и ограничение попыток входа;
- запрет HR-операций и чтения коллег для сотрудника, CSRF, Origin и Host;
- отсутствие секретных входных значений в ответах об ошибках;
- актуальные навыки после последней оценки, отсутствующий навык = 0, потолок без уменьшения уровня;
- исключение mandatory, завершённых мероприятий, невыполненных prerequisites и бесполезного прироста из кандидатов;
- отсутствие цели, Lead, смена роли с сохранением текущих ограничений аудитории;
- начало и продолжение активности, запрет завершения будущей сессии;
- завершение, повтор запроса, одновременные запросы и идемпотентность;
- отдельные посещения EV_036 и запрет повторного начисления за ту же сессию;
- сохранение после перезапуска и завершение после оценки в тот же день;
- новый профиль, ошибки схем/ссылок/дат, повтор импорта, явный update, защита от применения устаревшей партии;
- HR-агрегации, знаменатели и период участия;
- контракт AI с тестовым провайдером: допустимые ID, ≥3 разных фактора, кэш, инвалидация, тайм-аут, ошибочный/устаревший ответ и отсутствие провайдера.
- добровольное включение/пауза достижений, отсутствие ретронаград за импорт, XP за реальный прирост, потолок навыка и одинаковый день оценки;
- личные квесты, значки за разные мероприятия, сохранение после перезапуска, отсутствие XP в HR и чужом профиле;
- повторные и параллельные завершения без второй награды, в том числе после повторного открытия записи через импорт.

Есть одно предупреждение зависимости Starlette об устаревании поддержки httpx в TestClient. Проверки проходят; переход тестового клиента на httpx2 не выполнялся. Это не ошибка выполнения API.

## Полный стартовый набор

Выполнено: `uv run python scripts/check_dataset.py <локальный путь к career_quest_dataset>`.

| Проверка | Результат |
|---|---|
| Импорт | 200 сотрудников, 40 событий, 60 навыков, 32 профиля роли/грейда, 2 743 записи истории |
| Новый профиль с неизвестным ID | Импорт и основной серверный сценарий прошли |
| Завершение и повтор того же запроса | Прирост есть, повторного начисления нет |
| Доступ сотрудника к HR | Запрещён |
| Перезапуск | Результат сохранён |
| HR-срез | Около 0,189 секунды в одном локальном запросе |
| Профиль | Около 0,020 секунды в одном локальном запросе |

Измерения сделаны через FastAPI TestClient, без браузерного рендеринга и сетевой задержки. Это функциональный прогон, не нагрузочный тест, не p95 и не измерение времени реальной AI-рекомендации. В стартовом срезе алгоритм выявил 40 сотрудников без доступного полезного шага с учётом целей и ограничений каталога; причины доступны HR.

Датасет использовался по внешнему локальному пути, БД проверки была временной. Файлы организаторов в репозиторий не добавлены. Новая тестовая запись создавалась в памяти на основе профиля с действительно доступной self-paced активностью; его актуальные навыки использовались как новая оценка на дату среза.

Особенность источника: ежегодные completed для обязательных EV_001–EV_003 повторяются в реальном CSV. Импорт сохраняет записи разных дат; обязательные события остаются исключёнными из рекомендаций. Повтор добровольного completed допускается только для EV_036.

## Запуск и воспроизводимость

- `uv sync --locked` установил зависимости в отдельное чистое виртуальное окружение; импорт приложения прошёл. Использован уже доступный Python 3.12.14, установка Python с нуля этим действием не проверялась.
- Сервер запускался отдельным процессом через `python -m app serve --port <свободный порт>` на `127.0.0.1`.
- Настоящие HTTP-запросы к `/health`, `/ready` и `/openapi.json` прошли; в схеме 19 API-путей.
- В тестах использовался каталог с кириллицей и пробелами.
- `python -m compileall -q app scripts tests` и `git diff --check` прошли.

## Браузерный сценарий A + C + геймификация

Проверен настоящий FastAPI-сервер и UI из ветки C `34935be` с исправлениями интеграции. Использована отдельная временная БД и самостоятельный синтетический набор из тестов.

Через браузер выполнены создание HR, загрузка четырёх файлов, проверка/применение партии, создание аккаунта сотрудника, выход из HR и вход сотрудником. На странице «Достижения» участие изначально выключено, импортированная история не даёт XP. После включения выбран EV_GOOD, затем активность начата и завершена через историю. Навык Architecture изменился с 2 до 4, покрытие цели с 40% до 80%, начислено 40 XP, квест завершён. Обновление страницы сохранило результат; экран просмотрен визуально. Отсутствие AI отображалось отдельной ошибкой и не мешало сохранению результата.

Исправлены переход между ролями после выхода, возможность показать кнопку завершения mandatory в истории и обозначение подключённого callable как якобы проверенного AI-провайдера.
