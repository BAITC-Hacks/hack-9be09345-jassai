# Проверка серверной части A и интеграции C

Проверено 23 сентября 2026 года на Windows, Python 3.12.14. Проверены сервер, интерфейс C и личные достижения. Реальная LLM без ключа не проверялась.

## Автоматические тесты

Команда: `uv run pytest -q` (при разработке выполнена эквивалентная команда `python -m pytest -q` в окружении с закреплёнными зависимостями).

**107 passed за 109,75 секунды** на итоговой интеграции, включая 27 проверок геймификации, 29 проверок провайдера B, 4 сквозные API-проверки A→B→A и 9 Windows-проверок launcher/DPAPI. Тесты интерфейса: `node --test tests/*.test.mjs` — **33 passed**.

Проверены:

- одноразовая первичная настройка, вход, сессии, выход и ограничение попыток входа;
- запрет HR-операций и чтения коллег для сотрудника, CSRF, Origin и Host;
- отсутствие секретных входных значений в ответах об ошибках;
- актуальные навыки после последней оценки, отсутствующий навык = 0, потолок без уменьшения уровня;
- исключение mandatory, завершённых мероприятий, невыполненных prerequisites и бесполезного прироста из кандидатов;
- отсутствие цели, Lead, смена роли с сохранением текущих ограничений аудитории;
- начало и продолжение активности, запрет завершения будущей сессии;
- завершение, повтор запроса, одновременные запросы и идемпотентность;
- отдельные посещения EV_036 и запрет повторного начисления за ту же сессию;
- сохранение после перезапуска и завершение после оценки в тот же день;
- новый профиль, ошибки схем/ссылок/дат, повтор импорта, явный update, защита от применения устаревшей партии;
- HR-агрегации, знаменатели и период участия;
- контракт AI с тестовым провайдером: допустимые ID, ≥3 разных фактора, кэш, инвалидация, тайм-аут, ошибочный/устаревший ответ и отсутствие провайдера.
- добровольное включение/пауза достижений, отсутствие ретронаград за импорт, XP за реальный прирост, потолок навыка и одинаковый день оценки;
- личные квесты, значки за разные мероприятия, сохранение после перезапуска, отсутствие XP в HR и чужом профиле;
- повторные и параллельные завершения без второй награды, в том числе после повторного открытия записи через импорт.

Есть одно предупреждение зависимости Starlette об устаревании поддержки httpx в TestClient. Проверки проходят; переход тестового клиента на httpx2 не выполнялся. Это не ошибка выполнения API.

## Браузерный сценарий A + C + геймификация

Проверен настоящий FastAPI-сервер и UI из ветки C `34935be` с исправлениями интеграции. Использована отдельная временная БД и самостоятельный синтетический набор из тестов.

Через браузер выполнены создание HR, загрузка четырёх файлов, проверка/применение партии, создание аккаунта сотрудника, выход из HR и вход сотрудником. На странице «Достижения» участие изначально выключено, импортированная история не даёт XP. После включения выбран EV_GOOD, затем активность начата и завершена через историю. Навык Architecture изменился с 2 до 4, покрытие цели с 40% до 80%, начислено 40 XP, квест завершён. Обновление страницы и перезапуск настоящего сервера сохранили результат и два значка. Пауза не уменьшила XP; HR-профиль не показал личные достижения. Экран просмотрен визуально. Отсутствие AI отображалось отдельной ошибкой и не мешало сохранению результата. Обновлённая инструкция OpenAI в HR-настройках также проверена в браузере.

Исправлены переход между ролями после выхода, возможность показать кнопку завершения mandatory в истории и обозначение подключённого callable как якобы проверенного AI-провайдера.

## Интеграция B

Подключена ветка B `fe65baf`. Исправлены путь launcher с конечным обратным слэшем, изоляция установки Python, скрытый серверный процесс, слишком маленький лимит проверки ключа, противоречивое сравнение альтернатив и потеря `reason` в UI. Экран настроек показывает действующую настройку OpenAI через launcher.

`launcher.cmd /check` дважды прошёл на Windows с PowerShell 7.6.5, включая скачивание uv 0.12.17, Python 3.12.14 и зависимостей в отдельный каталог с кириллицей и пробелами. Проверены `/health`, `/ready`, HTML и JavaScript; сервер после проверки остановлен, runtime-state удалён. Windows PowerShell 5.1 на этой машине запрещает скрипты; политика не изменялась. Запуск двойным кликом в произвольной чистой Windows не считается проверенным.

`tests/test_b_integration.py` проверяет настоящий авторизованный маршрут A → `provider.recommend` B → валидация A, заменяя только внешний HTTP-транспорт тестовым ответом. Проверены факторы, точные серверные приросты, отсутствие ФИО/ID в отправляемом профиле, кэш, новый контекст после завершения, 502 при ошибке API/выбора и 504 при тайм-ауте. Вызовов настоящей модели эти тесты не делают.

Дополнительно локальная цепочка контекст A → факты/ответ B → схема A проверена на всех 200 профилях организаторов: 160 с кандидатами и 40 без доступного шага.

Windows-тесты исполняют функции из реального `scripts/launcher.ps1`: проверяют Responses output после reasoning-элемента, параметры запроса, отклонение incomplete/refusal/некорректных ответов, сокрытие ошибок, запись и чтение DPAPI на вымышленном ключе, ошибку повреждённого файла. Сеть и интерактивный ввод подменены; политики не меняются. На системах без Windows/PowerShell 7 эти девять тестов пропускаются явно.

## Границы проверки

Не подтверждены реальный API-ключ, облачный Responses API, качество выбора модели, задержка median/p95 и запуск на чистой Windows с её политиками. NVIDIA и резервный подбор не подключены к пользовательскому сценарию. Локальная авторизация не изолирует БД от владельца Windows-аккаунта.
